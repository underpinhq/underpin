# packages/ui: @underpin/ui

This package is the only source of `@underpin/ui`, the component library on Base UI and Tailwind v4 that `apps/web` is built on and that other products, Revinel among them, install from npm. It was published as `@dirstack/ui` up to 1.15.0, from `~/Sites/dirstack/ui`, which takes no more changes. The public `underpinhq/underpin` monorepo is a hybrid. Its `packages/ui` is a copy of this folder, and the sync replaces only that folder, so an edit made there is lost at the next sync. Every other `@underpin` package (`@underpin/utils`, `@underpin/analytics`, `@underpin/config` and the rest) is developed in that repository directly, by pull request there. `apps/web` pins the package as `"workspace:*"` and reads its source, so a silent fall-back to the npm copy is impossible and the dashboard needs no build of it.

Everything here ships to strangers, so the package stays standalone: no `@highseat/*` import, no import of itself by name, no `~` alias, no product logic. `oxlint.config.ts` rejects those imports in `src` and `scripts`. Its exports, component names and props are a public API: a rename or a removed prop is a major release with a line in [`MIGRATION.md`](MIGRATION.md).

What a screen looks like and how design work happens in Figma: [`DESIGN.md`](DESIGN.md).

## Rules

- Inside `packages/ui`, use relative imports (`../lib/variants`), never `~`: that alias belongs to `apps/web`.
- Colours are semantic tokens only, from the seven groups at the top of `styles.css`: surfaces (`bg-canvas`, `bg-surface`, `bg-overlay`, and `bg-well`, `bg-field`, `bg-knob` for a track, a field's ground and a switch knob), ink (`text-ink`, `text-ink-secondary`, `text-ink-muted`, `text-ink-inverse`), fills (`bg-fill-subtle`, `bg-fill`, `bg-fill-strong`), edges (`edge-subtle`, `edge`, `edge-strong`, `edge-solid`), the brand, focus, status (`text-danger-ink`, `bg-success-subtle`) and the chart series (`var(--color-chart-1)`). Never `bg-white`, `text-gray-*`, hex, `dark:` variants, or a `--gray-*` step directly: dark mode comes from the package's `light-dark()` tokens and `data-theme` on `<html>`, and a gray step is only ever reached through the token that names its job.
- **A product sets its own gray and accent** in its stylesheet, after this one's import, in its own `@theme` block or a `:root` rule. The gray is two numbers that the ramp and every neutral token (surfaces, ink, fills, edges, the scrim, the text on a solid) read: `--gray-hue`, and `--gray-chroma`, which scales the ramp's chroma (1 is the default warm gray, 0 a neutral one). `:root { --gray-chroma: 0; }` is a number, not a colour, so it passes `lint:colors`. The accent is the brand tokens themselves: `--color-brand`, `--color-brand-ink`, `--color-brand-subtle`, and `--color-brand-on` when the accent is light enough to need dark text; `--color-brand-edge` and `--color-chart-1` follow them. Never write a hue into a neutral token; `styles.test.ts` fails on one, and on a brand edge or first chart series that stops following the brand tokens
- An edge is a real `border` in an edge colour, and a shadow carries depth only. Never a box-shadow ring (`0 0 0 1px`, a `ring-*` class): it sits outside the box, a parent's clip cuts it off, and every state has to restate the shadow beside it. `styles.test.ts` fails on such a token and `scripts/shadow-edges.test.ts` at the repo root on such a class. A key (a segmented option flush with its track, a switch knob inset 2px) sits on a track with no edge of its own, the well. Edges are translucent (the ink at a fraction), so two bordered boxes never overlap: a shared seam drawn twice (`-ml-px`) comes out darker; a joined member drops its border instead, as `ButtonGroup` does
- A control that holds a value (typed or picked) is a field and takes `inputVariants`, as `Input`, `Textarea`, `SelectTrigger`, `Combobox`, `Autocomplete` and `DatePickerTrigger` do; never a `Button`, whose raised surface and medium weight read as a command beside the flat fields of a form. A trigger that runs a command (a toolbar's period picker, a filter) stays a `Button`
- Text sizes are theme tokens that carry their line height, so the class alone is the agreed pair: `text-2xs` (11/14), `text-xs` (12/16), `text-control` (13/16, one line inside a control), `text-copy` (13/20, text to read), `text-sm` (14/20), then Tailwind's heading steps, and `text-figure` with `figureClasses` for a headline number. Never an arbitrary `text-[0.6875rem]` or a bare `leading-*`; a `/leading` suffix (`text-xs/5`) is a deliberate exception and says why in a comment. A new size goes in `styles.css` **and** in `MERGE_CONFIG` in `lib/variants.ts`: without the second, `cn` and `variants()` read it as a colour and drop it beside `text-ink-muted`
- `src/tokens.ts` and `src/tokens.json` are generated: the opaque colour tokens as hex for code that cannot read CSS, and every token for the Figma library (see `DESIGN.md`). After changing a token in `styles.css`, run `bun run tokens` here; `tokens.test.ts` fails until you do
- A coloured role takes the same suffixes everywhere: the solid (`bg-brand`), `-ink` for text on the canvas, `-subtle` for a tinted fill, `-edge` for the 1px edge around that fill (`border border-success-edge` draws it), `-on` for text and icons on the solid. The brand is the one family a product swaps; `focus` stays fixed so focus is always visible.
- **One class merge per component.** `variants()` is tailwind-variants and already merges the `className` it is handed, so a component passes the caller's class into that call: `xVariants({ size, className })`, or `xVariants({ size, className: cn("own classes", className) })` when it layers its own. Never `cn(xVariants({ ..., className }))` (a second merge) and never `cn(xVariants(...), className)`, except on any Base UI part whose `className` is a state function (`autocomplete.tsx`, `combobox.tsx`, `tabs.tsx`, `segmented-control.tsx`, `switch.tsx`, `checkbox.tsx`, `radio-group.tsx`), which `variants()` rejects; each such site says so in a comment. `cn()` alone is for a component with no variants object
- Context uses the React 19 API: `use(Context)` and `<Context value={...}>`, never `useContext` or `<Context.Provider>`
- **An anchored popup never blocks the page for a mouse.** A menu, select, popover, combobox and autocomplete are non-modal: the page keeps scrolling, and one click outside closes the popup and reaches what is underneath, so moving between two controls takes one click. `Menu` and `Select` set `modal={false}` over Base UI's default; never pass `modal`. On a touch screen the menu, select and popover content each render a transparent backdrop (`popupBackdropClasses`) that takes the tap and stops a drag beside the popup, because a tap meant to dismiss must not land on a link. A dialog, sheet and drawer are tasks of their own and stay modal
- **Under `sm` only a dialog is a sheet.** A dialog is a task of its own (fields and actions), so on a phone it rises from the bottom edge as a Base UI Drawer you can swipe away, its shape read once as it opens (`usePopupSheet`). A menu, select, popover, combobox and autocomplete is a quick pick off a trigger, so it hangs off that trigger at every width, where the finger already is; it flips to whichever side has room and scrolls within it. A pick that grows into a small form of its own (the custom date range) renders a `Dialog` on a phone instead, through `useSheetWhileOpen`
- A media query goes through `useMediaQuery` in `lib/media.ts`, or `matchesMedia` for a one-off read inside a callback; do not add another `useSyncExternalStore` listener. Oxlint rejects a bare `matchMedia` in `apps/web` and `packages/ui`, and `localStorage` anywhere in `apps/web` but `lib/prefs.ts`
- Inter loads from `src/fonts.css` and the files in `src/fonts/`, which `scripts/fonts.py` at the repo root cuts from Google Fonts' source. Never edit them by hand and never load Inter from `@fontsource-variable/inter`: fontsource drops the alternates (`cv01`, `cv11`, `ss03`) that `--font-sans--font-feature-settings` turns on, so the setting would do nothing. `apps/web/index.html` preloads `inter-latin.woff2` by its path
- A component that uses state, an effect, a browser API or a Base UI part opens with `"use client"`, so a Next.js server component can render it. One that renders only markup or `useRender` has none, and a server component renders it directly
- The public surface (components, exported prop types) is not pruned here even when nothing in `apps/web` uses it: another product installs it

## Building and releasing

`apps/web` never builds the package. npm receives `dist`, built the way `packages/highseat` is (see its `AGENTS.md` for the mirror, the changesets and the kodeks pins, which work the same here):

- `bun run build` runs tsdown with `unbundle`, one built file per source module at the same path, then `underpin prepare-package`, which writes `dist/package.json` with the exports pointing at the built files. One file per module is what keeps each `"use client"` on the component it belongs to. Each `exports` entry is `{ types, default }`, so `require` reaches it too, and the `./*` wildcard maps a subpath to `components/<name>`
- `styles.css`, `fonts.css` and `fonts/` (the Inter files and their OFL licence) are copied to the root of `dist`. The stylesheet's `@source "./"` scans the folder it sits in, so it must stay beside the built `components` and `lib`, or a consumer's Tailwind generates none of their classes. A new file that `styles.css` imports goes into tsdown's `copy` list too
- `bun run check-exports` (after the build) fails a built module that lost its `"use client"`, an import of a package that is not a dependency or peer (a devDependency a consumer never installs), a stylesheet `url()` or relative `@import` with no file behind it, and an entry that does not load in Node. `bun run check-next` builds the Next.js app in `fixtures/next-app` against the packed tarball, with Turbopack and with webpack: its server page renders every component without `"use client"`, and its CSS must hold classes only the built components use. `package-ui.yml` runs both on every pull request that touches the package
- A dependency only some components use is an optional peer (`peerDependenciesMeta`), as `@tanstack/react-form` is for `form.tsx`
- **Releasing**: a change a consumer sees carries a changeset (`bunx changeset`, pick `@underpin/ui`). The "Version Packages" pull request bumps the version, `sync-ui.yml` mirrors this folder into `packages/ui` of `underpinhq/underpin` with the `UI_MIRROR_DEPLOY_KEY` deploy key, and leaves that repository's other packages and root files alone, and that repository's `release.yml` publishes with provenance through npm trusted publishing. Never publish from here. `sync-ui.yml` repeats the steps of kodeks's reusable sync workflow because that one reads the root `kodeks.release.json`, which belongs to the `highseat` mirror

## TanStack Charts

`TimeSeriesChart` is drawn with `@tanstack/charts` (pinned exactly; its minors may break) through the React adapter's `/react/tooltip` entry and the `motion()` renderer. The chart lives in `lib/time-series-plot.tsx`, and the `time-series-chart` entry loads it with `lazy()` behind `TimeSeriesChartSkeleton`, so an app imports the entry directly and still keeps the chart library out of its first paint. Nothing else may import `lib/time-series-plot` statically, or the library comes back into the importer's bundle. `Sparkline` is plain SVG on purpose, so a page that only lists sites never loads the runtime.

- A chart definition's identity is its update boundary: each new one rebuilds the scene. Memoize it only where its inputs are stable; `TimeSeriesChart` builds one per render because its callers hand it fresh rows and formatters every time
- The `motion()` renderer grows an entering bar from its `y1` and shrinks an exiting one back to it. A segment stacked on another bar (`y1` at that bar's top) therefore floats in mid-air while the bar under it animates; draw it from zero, behind the bar
- Grid lines default to 11% opacity and tick labels to 68%; set `strokeOpacity`/`opacity` to 1 to get the token colour as written
- A click pins the built-in tooltip unless the definition sets `tooltip.sticky: false`, which a chart with its own click action needs
- A chart declares gradients but not SVG patterns: a pattern lives in a sibling hidden `<svg>` and a mark reaches it with `fill: "url(#id)"`
- On a touch screen a tap leaves the bucket focused and its tooltip open; `TimeSeriesChart` dismisses it on lift through the `dismiss` the tooltip body receives
- A line that changes style partway (the running bucket, dashed) is two line marks over the whole series with the curves `splitCurve` (`lib/chart-curve.ts`) returns: each draws its own segments of the curve the whole series makes, so the parts meet on one tangent and run along the area's edge. Never split the data into two series: each part would bend on its own and leave the area
